# Spec: Stage 7 — Lab page

## What

A `/lab` route with its own nav icon (a flask). For now it says the section is coming soon and offers a small runner game in the site's style: a teal pixel dino jumping code-themed obstacles. The visitor's best score is kept in `localStorage`.

## Why

The Lab is where pet projects will live. Until the first one ships, the page should still be worth a visit rather than an empty placeholder.

## Scope

**In scope:**

- `app/lab/page.tsx`: heading, "Coming soon..." line, a short description of what the Lab is for, and an invitation to beat the owner's record.
- A `FlaskIcon` and a `lab` item in the header nav, between skills and contact.
- The runner game (`components/runnerGame/`):
  - A canvas game on the GSAP ticker, with our own pixel sprites.
  - Obstacles: `{ }`, `</>`, a bug, and a flying `;`.
  - Jump with Space/ArrowUp or by tapping the canvas.
  - The score, plus the best score saved in `localStorage`.
  - It plays on every layout.
- The owner's record as a constant (`constants/lab.ts`).
- e2e: `e2e/lab.spec.ts`, plus the new nav link in `e2e/header.spec.ts`.
- Docs: README, PROGRESS, AGENTS layout list.

**Out of scope:**

- The barbershop project, and any real pet-project apps.
- A global leaderboard, or any server-side score storage.
- Ducking. Every obstacle can be cleared by jumping or by running under it, so touch and keyboard play the same.
- Sound effects.

## Approach

- **Page.** A server component built from `PageShell`, `CodeTag`, `Heading` and `TextSplit`. One centred column on every layout: the text, then the game.
- **Field reveal.** Before the first run only the dino's corner of the field shows, centred under the text, with an accent "Press Space or click to play" prompt. Starting a game opens the field out to full width. This is done with a `clip-path` plus translate transition on a full-size canvas, so the world never rescales.
- **Engine.** `engine.ts` is framework-free:
  - A fixed 600×150 logical world, scaled to the canvas width.
  - Gravity and a jump impulse, randomised obstacle gaps, and speed that ramps with the score.
  - AABB collision on inset hitboxes.
  - Fliers only appear after a score threshold, at either jump height or overhead height.
- **Canvas** (`RunnerGame.tsx`). It reuses the backdrop's patterns:
  - DPR capped at 2 and a `ResizeObserver`.
  - Theme colours read from CSS custom properties.
  - `gsap.ticker` with `deltaRatio(60)`, so speed doesn't depend on frame rate.
  - It waits for `usePreloaderDone()`.
  - It pauses when the tab is hidden or the window loses focus.
- **Keyboard.** Keys are handled on `window`, but not while focus is on a link, button or form field.
- **Persistence.** `hooks/useBestScore.ts` follows the `useSyncExternalStore` shape of `useMediaQuery`. Storage access is wrapped in try/catch, the server snapshot is `0`, and it stays in sync across tabs through the `storage` event.
- **Accessibility.** The scores are DOM text below the canvas, so screen readers and tests can read them. The canvas is `role="img"` with an accessible label that describes the controls.
- No new dependencies.

## Acceptance criteria

- [ ] The header shows a flask "lab" item on every layout, marked `aria-current` on `/lab`.
- [ ] `/lab` shows the accent "Lab" heading, "Coming soon...", the description, and the record line.
- [ ] Space, ArrowUp or a tap starts the game and jumps. Hitting an obstacle ends the run, and the same input restarts it.
- [ ] A new best score survives a reload.
- [ ] No horizontal overflow on mobile, and the page fits the desktop frame without scrolling.
- [ ] Lint, typecheck, `lab.spec.ts` and `header.spec.ts` pass.
